# CRM Security Remediation — «МедЦентр»

_2026-10-03. План исправлений по итогам статического аудита (`CRM_AUDIT.md`, разделы 18–19). Значения паролей, ключей и персональные данные здесь не приводятся. Исправления выполняет разработчик CRM; СМЛаб код CRM не меняет._

## P0 — до любого интернет-доступа

| # | Проблема | Что сделать | Проверка |
|---|---|---|---|
| P0-1 | ~72 маршрута из 138 не проверяют вход (создание/отмена/перенос записей, изменение пациентов и врачей, печать документов с ПДн, касса, поиск пациентов); общий `auth_middleware` определён, но не подключён | Единая проверка сессии и роли для всех маршрутов, кроме входа и статики интерфейса; изменяющие действия — только POST с CSRF-защитой | Каждый маршрут без сессии → редирект на вход / 401 |
| P0-2 | Пароли пользователей хранятся открытым текстом (`users.password_plain`) и выводятся в HTML; хэш — SHA-256 без соли | Удалить `password_plain` из базы и интерфейса; хэш — bcrypt/argon2 с солью; сменить все пароли сотрудников | Столбца нет; пароли нигде не отображаются |
| P0-3 | Секрет подписи сессий записан в исходном коде (и в копиях файлов) | Сгенерировать новый секрет, хранить вне кода (переменная окружения / защищённый файл); старый считать скомпрометированным | В коде нет секрета; старые сессии недействительны |
| P0-4 | Вход врача без пароля, если пароль не задан | Запретить вход без пароля; задать пароли всем | — |
| P0-5 | `/uploads` (документы пациентов) и `/reports` раздаются без авторизации | Отдавать файлы только через маршрут с проверкой сессии и прав | Прямой URL без сессии → отказ |
| P0-6 | Сервер слушает все интерфейсы по HTTP | Не открывать порт 8000 в интернет; в сети клиники — ограничить доступ; для внешнего доступа — только HTTPS через отдельный шлюз/VPN | Порт недоступен снаружи |
| P0-7 | Токен бота MAX хранится в базе в открытом виде | Перевыпустить токен после исправлений; хранить вне базы или зашифрованным | — |
| P0-8 | Реальная база, бэкапы, документы пациентов и выгрузки (`audit_report.txt`) лежат рядом с кодом и попадают в архивы | Исключить данные из любых репозиториев и пересылаемых архивов; хранить бэкапы зашифрованно, с ограниченным доступом | В архиве кода нет `.db`, `uploads/`, бэкапов, выгрузок |
| P0-9 | Нет тестовой среды | Сделать **обезличенную** копию базы (без реальных ФИО, телефонов, e-mail, дат рождения, паспортов, диагнозов, файлов) для разработки и проверки | Разработка ведётся только на обезличенной копии |

## P1 — до интеграции сайта

| # | Что сделать |
|---|---|
| P1-1 | Аутентификация API для сайта: ключ сервиса, HTTPS, ограничение по IP / VPN, журнал обращений (`CRM_API_REQUIREMENTS.md`, раздел 7) |
| P1-2 | Отдельный серверный API/адаптер для сайта, а не HTML-маршруты интерфейса; минимальный набор данных |
| P1-3 | Нормализация телефонов пациентов (10 цифр после +7) и защита от дублей по телефону |
| P1-4 | Связь врач ↔ услуга (и цена у врача, если различается) |
| P1-5 | Полноценная модель расписания: дни, часы, перерывы, выходные, исключения, отпуска; вычисление свободных слотов |
| P1-6 | Защита от двойной записи: проверка пересечения интервалов в транзакции; резерв слота |
| P1-7 | Правила отмены и переноса на стороне CRM; дата отмены, источник записи |
| P1-8 | Идемпотентность создания записи |
