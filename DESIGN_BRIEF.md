## 1. Продукт

Сайт медицинской клиники «Смлаб». Один филиал, адрес: Западный обход, 42к2.

Сейчас проектируется **визуальный прототип на mock-данных**. CRM, backend, API и база данных не проектируются.

---

## 2. Целевая задача сайта

Сайт существует, чтобы пациент **завершил запись сам, за минуту, без звонка в клинику**.

Четыре задачи по приоритету:

1. Запись на медицинскую услугу.
2. Поиск информации об анализах.
3. Запись на сдачу анализов.
4. Авторизация и личный кабинет.

**Главный критерий успеха дизайна:** человек, зашедший впервые с телефона, записывается к врачу, ни разу не задумавшись, что делать дальше.

---

## 3. Основные пользовательские сценарии

### Сценарий 1 — Запись к врачу

```
Услуга → Врач → Дата и время → Данные / код → Подтверждение → Вы записаны
```

Для авторизованного пользователя шаг данных пропускается. При входе со страницы врача или услуги соответствующий шаг также пропускается — минимальный путь составляет 3 экрана.

### Сценарий 2 — Поиск информации об анализе

Человек пришёл узнать цену, срок или подготовку к анализу, который ему уже назначили. **Запись не является его целью.** Информация должна открываться сразу, без форм и без принуждения к записи.

### Сценарий 3 — Запись на анализы

```
Каталог → Выбранные анализы → Дата и время → Данные / код → Подтверждение → Вы записаны
```

При выборе одного анализа экран «Выбранные анализы» пропускается.

### Сценарий 4 — Управление записью

Личный кабинет: посмотреть, перенести, отменить.

## 5. Визуальное направление

**Современная частная медицина:** светлый интерфейс, профессиональный, спокойный, чистый, дружелюбный.

### Что это означает на практике

| Делаем | Не делаем |
|---|---|
| Много воздуха, крупные отступы | Плотные таблицы и мелкий текст |
| Мягкие скругления, лёгкие тени | Резкие углы, тяжёлые рамки, градиентный «глянец» |
| Спокойная подача, конкретные формулировки | Рекламный тон, восклицательные знаки, давление |
| Фотографии людей — живые, естественные | Стоковые улыбки со скрещёнными руками и пробирками |
| Простые линейные иконки | Объёмные цветные 3D-иконки |
| Цвет как навигационный сигнал | Цвет ради украшения |

### Тон интерфейсных текстов

Спокойный и конкретный. Пациент часто заходит на сайт клиники в тревоге — интерфейс не должен добавлять напряжения.

Запрещённые формулировки (`PROJECT_CONTEXT.md`, раздел 2.4): «Администратор свяжется с вами», «Ожидайте подтверждения», «Мы перезвоним для подтверждения», «Заявка принята». Результат записи формулируется как свершившийся факт: **«Вы записаны»**.

## 6. Brand direction: pink + blue

Подтверждённые бренд-цвета: **розовый** и **голубой** (FACT). Конкретные значения ниже — **предложение**, подлежит уточнению после получения логотипа (UNKNOWN).

### Роли цветов

Разделение ролей обязательно, иначе два ярких цвета начнут конкурировать:

| Цвет | Роль |
|---|---|
| **Голубой** | Опора и доверие. Шапка, ссылки, иконки, информационные состояния, активные элементы навигации |
| **Розовый** | Действие. Primary CTA, выбранный слот времени, акценты, метки акций |
| **Нейтральные** | Основа интерфейса. 80%+ площади экрана — белый и светло-серый |

**Правило:** на одном экране **один** розовый primary CTA. Если розовых кнопок две — ни одна не работает.

### Палитра — перенесена в канонический файл

Конкретные значения здесь больше не приводятся, чтобы не возникло второго источника истины (PD-19).

**Канонический источник токенов:** [`design/tokens.css`](design/tokens.css).

Одно уточнение по итогам дизайна: в этом брифе предполагалось, что primary CTA заливается `pink-600`. В финальном Design v1 для этого используется **`pink-700`** — он и проходит контраст (5.68 против 4.11).

**Контраст фактической палитры проверен**, найдено 5 групп нарушений — см. [`docs/CONTRAST_AUDIT.md`](docs/CONTRAST_AUDIT.md).

### Типографика

Inter с системным фолбэком. Типографическая шкала перенесена в канонический файл токенов — [`design/tokens.css`](design/tokens.css).

Минимальный размер основного текста — **16 px**. Мельче только подписи и служебные метки.

## 8. Требования к mobile 390 px

| Параметр | Значение |
|---|---|
| Frame | 390 px |
| Боковые поля | 16 px |
| Сетка | 4 колонки |

| Вертикальный ритм секций | 32–48 px |

### Обязательные правила для мобильной версии

- **Primary CTA не должен уезжать за экран.** В мастере записи кнопка перехода к следующему шагу закреплена внизу.
- **Календарь и сетка слотов** проектируются для мобильного отдельно, а не сжимаются из десктопа.
- **Поле ввода телефона** вызывает цифровую клавиатуру, поле кода — тоже.
- **Таймер резерва** виден без прокрутки на всех экранах мастера.
- **Навигация** — бургер-меню, но кнопки «Записаться» и телефон остаются видимыми в шапке.

Мобильный экран проектируется **первым** для сценариев из `PROJECT_CONTEXT.md` PD-17, десктоп — расширением.

## 10. Правила работы с MOCK / FACT / UNKNOWN

Четыре статуса из `PROJECT_CONTEXT.md`. Для дизайна важны три правила:

### FACT — можно показывать как сведения о клинике

Название «Смлаб», один филиал, адрес «Западный обход, 42к2», розовый и голубой как бренд-цвета.

### UNKNOWN — placeholder в квадратных скобках

```
[Телефон]  [Режим работы]  [Логотип]  [Цена]  [ФИО врача]
[Название услуги]  [Название анализа]  [Срок]  [Подготовка]  [Акция]
```

Placeholder ставится **буквально, в квадратных скобках**, и остаётся видимым в макете. Заказчик должен увидеть, чего не хватает.

### MOCK — только там, где без наполнения не оценить вёрстку

Разрешено для: сетки карточек врачей, списка анализов, календаря со слотами, состава комплекса, карточек акций.

**Требования к MOCK (в редакции PD-20):**

- Имена врачей — очевидно условные. Например «Врач А. А.», «Специалист №1». **Запрещено** использовать правдоподобные ФИО, которые можно принять за реальных сотрудников.
- **В пользовательском интерфейсе MOCK не помечается** — ни бейджами, ни надписями, ни легендой. MOCK это внутренний статус данных для разработки.
- Разделение обеспечивается в коде и документации: mock-данные лежат в отдельных изолированных файлах и удаляются одним действием при подключении CRM.
- Mock-данные не выдаются за реальные сведения клиники — ни в текстах, ни в метаданных страниц.

### Запрещено придумывать

Награды, лицензии, отзывы, статистику, количество пациентов, медицинские гарантии, скидки, телефоны, реальные цены, медицинские рекомендации.

## 12. Требования к accessibility

Аудитория медицинской клиники включает пожилых людей и людей в плохом самочувствии. Доступность здесь не формальность.

### Обязательно

| Требование | Значение |
|---|---|
| Контраст основного текста | не ниже 4.5 : 1 |
| Контраст крупного текста и элементов интерфейса | не ниже 3 : 1 |
| Минимальный размер основного текста | 16 px |
| Область нажатия на mobile | не менее 44 × 44 px |
| Видимый фокус | у всех интерактивных элементов, контур не менее 2 px |
| Цвет не единственный носитель смысла | занятый слот отличается не только цветом, но и начертанием или иконкой |
| Подписи полей | постоянные, не исчезающий placeholder вместо label |
| Ошибки форм | текстом рядом с полем, не только красной рамкой |
| Таймер резерва | изменение состояния сообщается текстом, а не только цветом |
| Масштабирование | интерфейс не ломается при увеличении текста до 200% |

### Специфично для этого продукта

- **Сетка слотов** проходится с клавиатуры, каждый слот доступен как отдельный элемент управления.
- **Поле кода подтверждения** позволяет вставить код целиком, а не только вводить посимвольно.
- **Календарь** различает «недоступен» и «не выбран» не только оттенком.

## 13. Структура основных страниц

### Главная

```
Шапка
Первый экран: заголовок + два действия («Записаться к врачу», «Сдать анализы») + поиск
Основные направления (плитки категорий)
Популярные услуги с ценами
Анализы: поиск + популярные исследования + вход в комплексы
Врачи: горизонтальная лента карточек
Акции
О клинике коротко
Контакты: адрес, карта, [Телефон], [Режим работы]
Подвал
```

### Каталог «Услуги и цены»

```
Шапка → Хлебные крошки → Заголовок → Поиск → Категории (боковая колонка или чипы)
→ Список услуг с ценами → Подгрузка ещё
```

### Каталог врачей

```
Шапка → Заголовок → Фильтр по направлению → Сетка карточек врачей
```

### Карточка врача

```
Шапка → Фото + [ФИО врача] + специализация + стаж
→ Услуги врача с ценами → Ближайшие свободные слоты → CTA «Записаться»
```

### Каталог анализов

```
Шапка → Заголовок → Крупный поиск → Категории → Вход в комплексы
→ Список анализов: название, цена, срок, метка подготовки, кнопка добавления
→ Плавающий счётчик выбранных
```

### Страница анализа

```
Шапка → Название → Цена, срок, метка подготовки → Акция (если есть)
→ Подготовка (раскрывающийся блок) → Описание
→ CTA «Записаться» + «Добавить к выбранным»
```

### Мастер записи

```
Шапка (упрощённая) → Stepper → Контент шага → Таймер резерва (с шага выбора времени)
→ Кнопка перехода к следующему шагу
```

### Личный кабинет

```
Шапка → Ближайшая запись (выделенный блок с действиями)
→ Будущие записи → Прошедшие записи
```
